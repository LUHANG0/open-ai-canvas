---
title: 生成作品存储与恢复
description: 生成前容量检查、作品检查点和暂存副本清理的合同
---

生成成功与作品保存成功是两个阶段。保存失败沿用原任务、资源上传键和计费订单恢复，不重新请求模型，也不因保存重试创建第二笔生成收费。

## 生成前检查

`task_creation.go` 在创建任务和计费预占前调用 `task_storage_admission.go`。产出文件的任务检查账号文件容量、素材数量、画布与素材结构化数据用量，以及 UTC 自然日上传额度是否仍能容纳一个最大生成文件。日额度采用现有的严格小于上限语义；恰好只剩一个最大文件的额度也会拒绝。

该检查不消耗上传额度，不预留未知产物大小，也不保证多任务、多产物均能保存。实际写入仍由现有资源存储事务和配额预留检查并发、真实字节数及归属。文本任务不使用文件配额检查。结构化用量复用 `UserStructuredStorageUsage`，不额外扫描任务、结果和调用日志。

## 检查点与副本顺序

1. 下载或内联结果先进入 `media-staging`，检查点记录安全的暂存文件名。
2. 资源按原任务和产物序号对应的上传键持久化。恢复时优先寻找同一账号的已就绪资源。
3. 将资源 ID 和已清空的暂存文件名写入受任务租约保护的检查点。
4. 第 3 步成功后删除暂存副本。检查点写入失败时保留副本；删除失败只记录警告，不撤销已经保存的资源。

最终素材登记失败时，恢复仍可使用已就绪资源，不要求原暂存文件或仍有效的上游地址。恢复继续遵循原有租约、取消、账号归属、退款订单和手动重试限制。

## 暂存容量与清理

暂存文件采用稀疏文件预留，当前总预算为 512 MiB。因其他副本占满预算产生的错误可进入原任务的有界保存恢复流程；单次预留超过预算等非法请求仍为不可重试错误。不会为了保存而重新生成。

24 小时仅是未引用暂存文件的清理门槛。清理前按任务 ID 游标分页扫描排队、运行及失败任务的加密检查点，不设固定总条数上限，也不按任务年龄排除仍可手动恢复的失败结果。查询或检查点解密失败时保留暂存文件。成功、取消或没有检查点的任务不构成这层恢复引用。

保留中的文件仍计入暂存预算；保护结果可能使新的保存暂时等待，不能以释放空间为由删除唯一副本。该流程只清理暂存副本，不删除素材、资源对象、数据库记录或用户文件。

## 验证边界

专项覆盖 SQLite 和隔离 PostgreSQL 的配额边界、账号隔离、检查点写失败、资源复用、超过 1000 个检查点的分页保护、不可读检查点和暂存空间恢复。使用合成媒体与本机替身；真实模型、生产桶和真实扣费不属于这些测试。
