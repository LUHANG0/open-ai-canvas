# 发布产物保留与清理

本合同用于梦层服务器发版后的资源收尾。发布成功和真实入口验收完成后执行；已有发布失败、回退、恢复或构建任务时先保留现场。规则本身不安装定时任务。

当前站点的服务器规则说明放在 `/opt/mengceng/ops/host-updater/release-retention.md`。它是运维执行约定，不是更新器自动执行配置；每次发版的执行者按本合同完成收尾并留证。

## 保留范围

- 当前 Web、Backend、Agent 的镜像与恢复来源，以及更新器声明的一份回退。组件可能来自不同提交，不按某个目录名字推断整站版本。
- 更新器 profile、源 Compose、环境、nginx、systemd、进程工作目录和容器挂载仍引用的文件。依赖可能落在更旧目录，因此允许超过两个目录，但必须记录具体引用原因。
- 数据库、用户素材、密钥、独立备份、尚未完成的发布事务及唯一源码。它们不属于构建缓存；本规则不改变备份的保留和恢复合同。
- 当前和上一版网页的 hash 资源按 Web 发布器与入口脚本的合同保留，支持尚未刷新的旧标签页；不直接清理业务数据卷。

自定义更新器以运行容器、`custom-current.json`、当前事务和冻结后的 active Compose 为依据。历史 `current` 链接、目录日期或 Docker 的 reclaimable 标记均不能单独决定删除。

## 清理范围

发布成功后删除没有引用的旧发布目录、重复源码副本、上传归档、已完成的临时容器和编译镜像。保留小型的提交、摘要、验收和删除记录，不再无限保存完整版本。

删除旧源码前，先验证其 Git 清单是否足以恢复；额外或来源不明的修改保留精确差异及校验记录。差异归档以已核实的 Git 提交为恢复基线，文件内容按摘要去重；验证基线或差异内容能逐项重建所需文件后，才移除原副本。环境及敏感恢复材料只保存在服务器私有目录，不能提交到 Git。

镜像必须先核对所有容器、当前组件、回退组件及进行中任务。只清理明确归属梦层的无引用镜像，遇到依赖关系或用途不明时保留并记录；其他项目的镜像和数据不在范围内。

站点专用 BuildKit 缓存在没有活跃构建时使用工具提供的清理入口，目标保留约 4 GiB。清理前后记录工具统计与真实可用空间；缓存的逻辑大小可能包含共享层，不能当作实际释放量。禁止直接删除 BuildKit 数据卷，也不执行包含 volumes 的 Docker 全量清理。

## 执行顺序与复核

1. 记录磁盘、服务身份、健康、组件镜像、更新器事务和真实引用，生成具体保留/删除清单。
2. 校验待删路径位于明确的发布根目录内，没有符号链接、业务数据、挂载或活跃进程引用；完成必要源码差异保全。
3. 删除前再次读取运行服务和事务，发现变化则重新盘点，不执行过期清单。
4. 分别清理历史目录、无引用项目镜像和构建缓存；每项记录结果，保留当前/回退镜像与业务数据。
5. 核对服务镜像和启动时间未变，检查 ready、Agent 健康、公开页面和必要静态资源；记录实际释放空间、保留项及原因。

运维记录放在服务器本次任务的私有目录和本机 `.local`，不持续追加到开发约定正文，也不把目录存在当作已经完成验证。

上述步骤串行执行，任一前置校验失败都必须停止后续删除。使用程序编排时检查子进程退出状态，不能把多条清理命令无条件接在一起。
