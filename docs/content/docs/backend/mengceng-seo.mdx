首页初始 HTTP HTML 仍包含内置旧标题和描述，与运行后 DOM 不同。因此后台保存已解决运行后的元数据，尚未解决初始 HTML 的动态发布与公开正文渲染。robots、sitemap 和 Nginx 改动仍未部署，站长平台验证与收录提交仍未执行。

相关诊断依据：[Cloudflare Error 1010](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1010/)。不要因为默认客户端被拦截就全站关闭安全策略。

## 后续实施顺序

### 已实现的服务器 HTML 合同

新增 `/api/public/brand-site/html/head` 与 `/api/public/brand-site/html/body` 两个 `text/html; charset=utf-8`、`no-store` 公开接口，分别读取 `Appearance()` 与 `PublicBrandSite()`。HTML 模板统一转义文本；正文只输出已发布且可见的标题、描述和条目，不输出草稿、上一版、管理员信息或媒体资源标识。接口不接收任意模板、目标地址或资源路径。

生产 Nginx 使用 SSI 将公开元数据写入 HTML 的 head，并仅在根路径（含查询参数）的初始 root 中输出语义正文。`/_brand-seo/head`、`/_brand-seo/body` 为固定 internal 入口，子请求不带 Cookie 或 Authorization，不使用公共代理缓存。其他应用路由保留原加载入口。外观读取失败时使用内置 head 兜底；正文读取失败时交给客户端原有加载与错误处理，不能宣称此时仍有完整服务端正文。

Vite 开发服务不处理 SSI 注释，因此仍使用内置 metadata 与原加载界面；构建产物经 Nginx 才能验证服务器拼装。两个公开片段分别读取当前公开配置，不构成跨外观设置与官网发布的单一数据库快照。它们是语义 HTML 首屏，不是整个交互官网的 React hydration；前端启动后仍按现有流程请求公开内容并渲染完整页面。

专项测试覆盖未发布草稿不外泄、隐藏版块不输出、发布与恢复即时反映、HTML 与属性字符转义。真实 Nginx 验收需要覆盖首页、带查询参数首页、登录路由分界、robots/sitemap 类型、internal 入口限制和后端不可用时的 head 兜底。SQLite 测试使用隔离内存库，不以生产连接为输入。

以下顺序中的首屏 HTML 与爬虫入口已有源码实现，实际发布与站长平台提交状态以本次验收记录为准：

1. 在 CDN/代理和源站日志中核实真实搜索爬虫访问，使用站长平台的实时 URL 测试确认首页、JS/CSS、公开官网内容接口可达。不能仅通过伪造 User-Agent 判断真实 Googlebot 可达性。
2. 让首页初始 HTML 包含实际发布的品牌正文和 metadata。当前 `web/index.html` 只提供加载界面，`pages/welcome/index.tsx` 等待官网接口后渲染。预渲染或服务端渲染应使用 Published 内容，并与 CMS 发布、恢复、缓存失效相连；不能将 Draft、私有资源、历史发布副本或硬编码旧文案当作公开正文。
3. 沿后台外观设置合同更新标题和描述。建议标题“梦层 MengCeng｜AI 视频创作、创作画布与短剧工作台”；建议描述“梦层 MengCeng 面向独立创作者与小型团队，提供 AI 视频与图片创作、参考素材管理、创作画布及短剧项目工作流，从创意讨论、角色设定到分镜组织，集中推进影像创作。”。应核实线上权限和开放能力后应用，不承诺免费、速度或尚未验证的效果。仅修改 index.html 会被现有外观配置覆盖。
4. 建立可直接阅读的功能介绍页，再从首页与页脚加入链接并纳入 sitemap。候选路径为 `/ai-video`、`/ai-canvas`、`/ai-short-drama`；这些路径只是建议，目前尚未实现。每页写明使用对象、输入和输出、具体步骤、真实示例、限制与相关教程，CTA 再进入登录和对应创作入口。
5. 增加与可见内容一致的 WebSite/Organization 等结构化数据及可公开抓取的分享封面。不要伪造评分、价格、用户评价；不能将 schema 当作排名或富媒体结果保证。
6. 将认证页面、私有工作区和错误页的索引策略与路由生命周期连接。错误页应返回真实 404 或有明确 noindex；不要把全站统一设为 noindex，也不要用 robots 屏蔽替代索引移除。
7. 绑定并核实站长平台所有权，提交 sitemap，按页面检查抓取和索引。需要已登录的平台账号和域名验证条件；官网登录不等于站长平台权限。

## 公开功能页、教程与自动收录（第二阶段）

### 内容与路由

`backend/internal/publicsite/content/*.json` 是公开阅读内容的唯一目录；添加有效的 `published: true` 文件并构建发布后，功能/教程索引、服务端路由、相关文章、sitemap 与提交扫描会一起发现它。`published: false` 不进入公开目录；related 只允许引用已发布内容，配置错误会在专项测试中失败。内容目前随版本发布，不属于品牌 CMS 草稿，也不是后台富文本编辑器。

初始内容为三篇功能详解（AI 视频、创作画布、短剧项目）和四篇教程（视频提示词、参考图生成、画布素材整理、短剧分镜）。加上 `/features`、`/tutorials` 两个索引和首页，共十个 sitemap URL。工作台、登录、管理后台、私有素材、个人项目和 API 路径不进入 sitemap。

每个阅读页直接返回完整 HTML，包括唯一标题、描述、canonical、分享图片、WebPage/Article 与 BreadcrumbList JSON-LD。样式和镜头文字整理器使用独立小资源；正文不依赖 JavaScript。所有内容经过 HTML 模板转义，JSON-LD 仅由 JSON 序列化产生。功能入口经已有 `/login?next=...` 合同返回工作台。

### 域名与发现

运行配置必须显式提供 `CANVAS_PUBLIC_BASE_URL` 根地址。Nginx 的公开页面、robots、sitemap 与 IndexNow 验证文件均转发固定后端接口，并去除浏览器 Cookie 与 Authorization；未知阅读地址返回 404 和 noindex。开发 Vite 使用相同后端目录；旧的静态 sitemap/robots 已移除，避免维护两份列表。

`lastmod` 采用作者更新字段和已发布配置的实际时间，不使用请求时间。首页 revision 只包含公开发布内容与公开外观字段，保存品牌草稿不触发首页新版本。修改正文时必须更新该文件的 `updatedAt`；修改公共模板如改变了可索引正文，也应更新相应内容日期。

### 提交与恢复

后台 `/admin/settings/seo` 可启用自动检查、保存百度普通收录 API token、选择 IndexNow，并记录 Google sitemap 登记情况。Google 读取已登记的动态 sitemap；普通功能页与教程不调用 Google 限定用途的 Indexing API，也不使用已停用的 sitemap ping。

每分钟检查发布目录，每轮最多处理十条。任务按平台、canonical URL、内容 hash 去重。已接受的当前版本不重复发送；更新、删除或取消发布会清理旧版本待提交记录。CAS 与两分钟租约保护跨实例领取，过期租约可恢复；外部平台已接收但本机尚未保存结果时仍可能重试，这是外部调用和本地持久化之间的边界。未声称外部投递恰好一次。

网络与平台故障采用指数退避，限流遵守有界 Retry-After；百度额度耗尽则等北京时间次日 00:05，最后一条成功响应 remain=0 也会阻止当日继续投递。十次失败或凭据错误进入需要处理状态；修正并保存配置会释放受阻任务。后台明确区分“待提交”“平台已接受”“等待配额”和“需要处理”，不会将 API 接受伪装成已经收录。

配置与队列复用 `system_settings`，键分别为 `seo_publication`、`seo_submission_state`，无新增表或 Schema 迁移。百度 token 与 IndexNow key 使用现有设置密钥加密保存，接口仅返回是否配置；配置 CAS 与脱敏管理员审计在同一事务内提交。平台错误只保存固定代码，不保存请求 URL、密钥或上游原始正文。出站仅允许固定官方地址，禁用重定向，并复用既有出站网络策略。默认采用 HTTPS；百度官方文档的旧 HTTP 接口需要独立显式开启 `baiduAllowHTTP`，界面提示推送密钥会明文传输。该选项不改变 IndexNow 的 HTTPS，也不关闭任何证书校验。

后续完整重建前端仍须从 `/opt/mengceng/shared/site-verification/` 恢复百度所有权文件。IndexNow 验证文件由当前运行配置动态提供，不依赖手动复制。

参考：[Google sitemap 与 lastmod](https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping)、[Google Indexing API 使用范围](https://developers.google.com/search/apis/indexing-api/v3/quickstart)、[百度普通收录 API](https://ziyuan.baidu.com/college/courseinfo?id=267&page=2)、[IndexNow 协议](https://www.indexnow.org/documentation)。
