# 创作历史跨设备同步

`/create` 的普通历史使用独立的账号数据接口，不属于 `creation-runs` 的执行租约、审批、报价或 Cloud Agent transcript。转入画布仍使用原映射。两台设备必须登录同一账号并连接同一后端；源码改动不会自动更新其他设备或服务器。第一阶段在打开、刷新、回到前台及网络恢复时对账，不新增 WebSocket。

## 缓存与旧历史

原账号 scope 中的 `creation-conversations-v1` 保持原样，作为迁移备份。新键 `creation-history-sync-v1` 使用账号隔离的 localForage，原子保存当前对话、服务端基线修订、待删除 ID 和本地冲突副本；正文和媒体不进入 localStorage。游客 scope 不自动并入账号。

新缓存不存在时先复制旧记录，随后按稳定对话与消息 ID 补传。同内容重试不重复创建或增加修订；云端较新时保留云端版本和本地冲突副本。失败不删除原键或待同步记录。单条历史缺失媒体不阻断其他历史补传和拉取。

页面显示“历史仅保存在本机／历史待同步／历史已同步／历史同步失败”，失败可重试，详细原因位于状态提示。状态仅说明历史保存，不代替任务生成状态。冲突副本保存在本机同步缓存，本阶段尚无独立恢复界面。新建空白对话仅在本地占位，首次有消息才补传。

## 接口与并发

接口使用登录 Cookie。后台请求额外携带 `X-Canvas-Expected-User`；当前 Cookie 已切到其他账号时，服务端拒绝旧请求。媒体上传和每一步分片同样携带此标识及取消信号。切换账号或离开页面取消本会话网络工作和后续 UI 更新。

| 接口 | 合同 |
| --- | --- |
| `GET /api/creation-conversations?after=<id>` | 当前账号摘要及删除标记，ID 升序，每页 100 条，`next` 为空表示结束 |
| `GET /api/creation-conversations/:id` | 一致性快照：摘要及逐条消息修订；其他账号记录返回 404 |
| `POST /api/creation-conversations/:id/sync` | `metadata: {revision,title,canvasId?}`、`messages: [{id,revision,data}]`，或独立的 `delete: true`；返回完整快照及 `conflicts` |

摘要含 `revision`、`metadataRevision`、`deleted`、服务端 `updatedAt`。标题与画布关联使用元数据修订，消息使用各自修订，首次为 0；不能提交整数组覆盖。`conflicts` 返回 `metadata` 或具体消息 ID，其他不冲突消息可提交。非法输入、资源越权及数据库错误整批回滚。

对话行写锁覆盖修订检查、消息与引用索引更新。SQLite 与 PostgreSQL 使用同一条件写锁方式。消息按不可变 `sequence` 排序，保证同毫秒创建的用户消息与回复不被随机 ID 排反；跨设备追加按服务器接收顺序合并，原 `createdAt` 保存在正文合同中。

同消息或元数据冲突时保留服务端版本及本机副本。拉取也比较原基线，不能把上传失败的旧缓存套上新修订覆盖云端。完成消息不能退回生成中。任务恢复仅订阅已有 `taskIds`、挂载原结果，不创建新任务或重复扣费。

删除保留永久 tombstone；从未成功上传的对话也可建立删除标记。旧设备随后迁移、追加或重命名同 ID 都返回删除状态。删除只清理历史正文与引用，不删除资源、素材或任务。

单请求最多 2 MiB、100 条消息；单条正文合同最多 256 KiB；单对话最多 5000 条消息、16 MiB 正文合同。客户端按条数与保守字节估算分批，每批成功后先持久化修订。

## 媒体边界

云端使用明确字段白名单。附件、引用、结果保存 `resource:<id>`，服务端检查资源归属及 ready 状态、任务归属、关联画布归属。渠道配置、密钥字段、嵌套技能配置、blob/data URL、签名和预览 URL 不写入云端聊天 JSON。

本地媒体复用上传能力，以原键作为幂等身份；内联/blob 媒体使用内容摘要。成功后缓存改用稳定键，展示地址由既有媒体能力生成。其他设备不依赖原设备 IndexedDB。缺失文件或只有未知远端临时地址的旧结果保留本地并报错，不静默丢媒体，不提交过期地址作为身份。

资源引用索引参与普通删除检查和孤儿清理。素材库主动“彻底删除”的现有语义保持，可能使历史媒体失效；删除历史不会触发物理删除。

## 已完成图片与视频的生成记录

创作消息的 `resultRecords` 与画布节点的 `metadata.resultRecord` 复用媒体绑定快照，不另建计费或结果管线。输出下方以紧凑单行摘要展示公开模型名、实测分辨率与比例、冻结耗时和实际积分；画布使用带背景、边框和圆角的信息卡片。完整摘要、像素、视频时长、完成日期及任务 ID 保留在 `title` / `aria-label`，没有可展开详情，也不将悬停提示视为键盘或触屏可展开入口。窄节点保持单行裁切，不换行；画布保留媒体信息开关，仅在缩放达到 `0.85` 且满足节点 LOD 条件时显示。

- 模型取完成任务的 `model`，交付时解析为公开名称；不是当前可编辑模型选择器。旧记录只使用原有产出模型/提交模型，不从新任务推断。
- 尺寸来自任务结果/物化媒体及浏览器实际解码，不使用请求质量、请求比例或节点预览框。快照绑定 `mediaKey`；URL 续签不改变身份，本地媒体转云端时同步重绑定匹配的 key，不重绑定过期快照。
- 有 `createdAt`、`completedAt` 且 `mediaStage=completed` 时记录「总耗时」，包含排队到服务端媒体保存；无保存阶段证据则记录「任务耗时」，只有执行开始时间时记录「生成耗时」。单行摘要缩写为耗时数值，完整描述保留在 `title` / `aria-label`。不使用当前时间或重载时刻补造完成时间。
- 金额仅使用 `billing.status=settled` 的 `actualAmountMicrocredits`（整数微积分）；缺失为「费用未知」，reserved/running/uncertain 为「结算中」，明确结算零显示 `0积分`。不展示预占报价，不做平均分摊。待结算快照由原有账号隔离的共享任务观察器更新，已结算记录不因旧预占响应倒退。
- 同一任务多输出只展示一次模型/耗时/费用，完整描述标注「本次任务合计」，单行摘要缩写为「合计」；画布由批次封面展示，子图仅保留自身媒体事实和任务描述。创作消息按 task ID 分组。重试仍是新 task ID，旧结果不借用重试任务的时间或费用。

历史同步仅接受有限字段的快照，`mediaKey` 必须属于同消息的 `resultStorageKeys`、`taskId` 必须属于 `taskIds`；继续检查当前账号资源 ready 与任务归属。快照只用于展示，不作为扣费依据；没有新表或数据库迁移。旧服务端不识别新增字段，前后端需一起发布。私有资源的签名解析和本地账号 scope 沿用既有实现。

## 验证

后续已按授权部署到正式站，数据库升级至 schema 60。发布前备份在隔离 PostgreSQL 中实际恢复并完成重复迁移检查；正式接口的并发追加、过期元数据冲突、删除后旧设备补传、预期账号不符 403 与匿名读取 401 均通过，合成测试历史已清理。真实浏览器的创作页显示“历史已同步”，手机历史抽屉可打开且无横向溢出。这些结果不代表真实生成任务、实际大媒体或两个真实设备的长期同步已验收；以下本地记录保留其原范围。

专项覆盖旧迁移、重复重试、并发合并、离线删除、防复活、账号取消、资源/任务归属、无级联删除、HTTP 鉴权与数据库迁移。浏览器结果和未覆盖状态以[待测试](/docs/progress/pending-test)为准。客户端协议夹具不等于真实双设备成功；收费模型、生产环境、大视频及其他后端实例需分别验收。
