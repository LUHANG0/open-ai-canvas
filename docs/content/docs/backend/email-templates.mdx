## 管理入口

管理员在「平台配置 → 邮件模板」编辑注册、登录、找回密码、绑定邮箱和更换邮箱五种场景；「邮件服务」页也提供入口。每个场景可编辑主题、正文标题、验证说明与页脚，使用 `{{brand}}` 引用实际发件人名称（未自定义时跟随站点品牌）。桌面、手机和纯文本预览均由后端同一渲染器生成，示例验证码固定为 `123456`，不发邮件、不产生真实验证票据。

验证码、十分钟有效期、禁止透露验证码的安全提醒由固定布局输出，管理员不能删除或通过变量改变。编辑内容作为文本转义，不执行 HTML、模板表达式或外部资源；不支持自定义脚本、图片或任意跳转链接。图文邮件采用表格与内联样式，输出 `multipart/alternative` 的 UTF-8 纯文本和 HTML 两个部分，Base64 按 76 列换行；兼容不显示 HTML 的客户端。

## 接口与保存

- `GET /api/admin/settings/email-templates` 返回 `setting`，包括 `revision`、五场景 `templates`、`defaults` 和可选 `updatedAt`。
- `PATCH /api/admin/settings/email-templates` 提交当前 `revision` 与五场景全部文案，成功返回版本加一的 `setting`。字段不能为空；主题/标题/说明/页脚分别最多 120/80/600/400 个 Unicode 字符。主题禁止换行，仅支持 `{{brand}}` 变量。
- `POST /api/admin/settings/email-templates/preview` 提交 `scene` 与 `template`，返回 `preview.subject/text/html`。客户端在无脚本权限的沙盒 iframe 中预览 HTML。

接口全部执行服务端管理员检查。存储复用 `system_settings`，键为 `email_templates`，不增加表或列，不需要 Schema 升级；SQLite 和 PostgreSQL 使用同一合同。首次不存在时只在内存提供默认值，不进行隐式写入。保存采用基于原始 JSON 的条件更新；首次保存使用主键冲突保护。过期版本或并发写入返回 409，后台保留调整并要求重新读取，不能自动覆盖。

模板设置与 SMTP 设置分离，保存文案不修改发件账号、密钥、加密方式、注册开关和邮箱白名单。未保存的模板切换场景时保留；离开或刷新前提示放弃调整。恢复默认只修改当前场景草稿，点击保存后生效。

## 发送路径与兼容

统一身份验证的注册/登录/绑定入口、旧注册验证码入口、旧找回密码入口和个人资料更换邮箱入口都调用 `auth.deliverVerificationEmail`。模板不改变验证码生成、用途隔离、票据就绪、限流和消费事务。发信失败继续保留各入口既有的失败/清理及账号枚举保护语义。模板不含密钥，SMTP 日志继续对明文、HTML、验证码和 Base64 回显脱敏。

默认模板随代码提供，新版本首次运行即可用于后续邮件；已有 SMTP 配置不需重新填写。部署和真实邮箱投递需在目标环境单独验收，本机模板预览不能证明邮箱收件箱分类。
