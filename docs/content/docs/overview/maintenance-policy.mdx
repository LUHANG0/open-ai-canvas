# 维护与分支策略

## 唯一维护基线

本项目以 `LUHANG0/open-ai-canvas` 的 `main` 分支作为唯一持续维护、测试和部署的代码基线。本机、服务器、自动更新器、安装脚本、本机 Agent 和容器镜像不得默认切换到其他仓库或历史工作分支。

部署前应确认：

- 本地工作区干净，并与 `origin/main` 一致。
- 后端健康接口报告的 commit 与目标 `main` 提交一致。
- 数据库在迁移前已有可恢复备份，迁移后通过结构版本和完整性检查。
- 前端、后端、Agent 和部署配置使用同一个提交，不混用历史二进制或旧构建产物。

## 临时分支

`feat/*`、`fix/*`、`refactor/*`、`perf/*` 和 `test/*` 只用于隔离开发、审查和回滚。完整合入 `main` 并通过集中验证后，应删除对应远程分支；删除本地分支或 worktree 前仍需确认工作区干净且没有未合入提交。

## 上游边界

`ddcat-ai/open-ai-canvas` 是本维护版本的上游来源，不是默认部署源。除非负责人明确提出同步需求，否则开发任务不得自动拉取、合并、覆盖或部署上游代码。确需引入上游能力时，必须在独立集成分支完成差异审计、冲突处理、数据迁移评估和全量回归，再决定是否合入 `main`。

保留上游仓库、作者和贡献者署名是许可证与项目历史要求，不代表当前运行版本由上游分支构建。
