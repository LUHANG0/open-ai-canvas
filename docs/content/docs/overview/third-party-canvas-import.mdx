# 第三方画布导入与同步恢复

画布顶部“导入第三方画布”支持 LibTV 和 TapNow。读取外部画布后显示节点、连线与跳过项目，确认后通过同一保存入口追加到当前画布。

## 保存结果

- 本地持久化成功、服务端尚未确认时，提示“已在本机保存，正在后台同步”，保留节点、连线和等待期间的编辑。等待超时只结束调用方的等待，不取消后台事务，也不恢复导入前的数组。
- 只有服务端确认后才提示保存到云端。本地持久化失败或明确的远端拒绝继续报错；当前页面内容保留，可重试保存。
- 同一批次重试按节点和连线 ID 去重，保留已存在节点的编辑与素材身份。正在确认时阻止重复执行；关闭并重新读取外部画布仍属于一次新的读取操作。

## 素材与刷新

媒体节点在进入编辑器及持久化快照之前绑定当前账号的素材身份。内嵌图片先落到当前账号的本地图片存储，节点与素材共用同一个按内容摘要生成的 key；该准备过程不发起模型调用或远端上传。等待本地准备期间发生的新编辑也必须保留。文本和空媒体占位节点沿用原有入库行为。素材先落盘，再由既有同步链路先提交素材、后提交引用它的画布操作。

刷新后，对已确认画布基线之后新增、且素材记录的画布 ID 与节点 ID 匹配的导入素材，恢复查询和补传。复制节点共享素材时保留全部候选归属。已确认节点、普通素材和其他画布的初始化规则保持原样；没有可信基线时继续沿用既有保守恢复逻辑。

资源上传合并账号校验头与幂等键，保持普通上传、直传准入、分片会话及 URL 导入在重试时使用相同资源身份。两类请求头不能互相覆盖。

导入绑定、保存及确认检查当前账号；切换账号后停止旧账号的导入调用。保存继续使用原修订、租约、账号归属和 mutation receipt 合同，重试不能绕过冲突检查或直接覆盖快照。

素材上传确认后，同步层只更新上传期间没有变化的媒体 URL、存储键及其别名，保留素材 ID，以及等待期间的标题、标签和媒体替换。已确认基线也采用相同的云端资源身份，避免下一轮保存把同一素材重新入库。

素材记录、资源文件和第三方 URL 各有自己的身份及访问规则。界面显示已同步不等于外站媒体永久可用；外部获取和物理存储仍由现有导入与资源链路负责。

## 实现与验证入口

- `web/src/pages/canvas/canvas-import-save.ts`：追加、素材绑定、去重和保存结果。
- 两个导入对话框及 `project.tsx`：共享保存入口和用户反馈。
- `user-data-sync.ts`：刷新初始化时识别未确认的导入素材。
- `services/api/resources.ts` 与 `resource-upload-identity.test.ts`：上传幂等键、账号校验与取消信号共存。
- `web/test/canvas-import-save.test.ts`、`core-recheck-sync-repro.test.ts`：等待、明确失败、编辑保留、重复确认、账号切换和刷新补传。

真实第三方读取、浏览器故障注入和生产发布分别记录验收范围，不将合成返回内容替代的测试称为外站端到端验收。该流程不提交生成任务。
