# 短剧创作全链路审计与优化报告

> 审计基线：`a855fa6`。独立分支：`refactor/short-drama-creation-audit-20260903`。基线标签：`audit/short-drama-creation-base-a855fa6`。
>
> 所有结论以当前分支代码、测试或运行验证为依据；不包含付费生成、真实计费配置修改或用户数据删除。

## 当前结论

短剧项目已经具备“项目 → 章节 → 角色与资产 → 分镜脚本 → 图片/动作预演/视频 → 交付与画布”的主体链路。本轮已修复审计中发现的数据丢失风险、跨章节错误恢复、生成前副作用、阶段提示语错配、失败步骤不可重试和部分成功不可达等问题；列表、空态、错误态和 PC 主路径也完成了非破坏性浏览器回归。仍未接入的是交付打包后端；真实模型生成与计费路径按约束保留为待用户确认项。

## 范围与边界

本轮实施覆盖 `web/src/pages/projects/`、项目 API 客户端、项目与画布衔接、相关前端测试，以及后端项目只读路径。后端、Admin、数据库、权限、计费和协议保持不变；只有发现阻断性正确性缺陷时才允许最小后端修复并单独记录。

不执行以下操作：

- 不触发真实图片、视频或文本付费生成。
- 不删除真实用户项目、章节、素材或产物。
- 不修改真实模型渠道、积分价格、权限或部署配置。
- 不对移动端做视觉重构，只验证 PC 样式没有泄漏到小屏规则。

## 首轮问题清单

| 优先级 | 发现 | 证据路径 | 用户影响 | 处理策略 |
| --- | --- | --- | --- | --- |
| P0 | 章节正文和镜头脚本刷新后丢失未保存修改，跨路由离开也没有统一保护 | `pages/projects/detail/chapters.tsx`、`workflow-production-workbench.tsx` 仅维护组件内 `dirty` | 长剧本编辑可能直接丢失 | 增加用户隔离的 IndexedDB 草稿、刷新恢复、保存后清理与路由/关闭保护 |
| P0 | 任务恢复遍历整个项目的完成任务，却使用当前已加载章节的资产与镜头快照物化结果 | `chapters.tsx` 恢复 effect 与 `storeGeneratedStoryboard` 闭包 | 切换章节后可能丢资产引用或出现错误替换冲突 | 恢复只处理当前已加载章节；打开目标章节时继续恢复 |
| P0 | 生成按钮先保存镜头版本，再校验模型渠道是否完整 | `workflow-production-workbench.tsx` 的 `generateArtifact` | 配置错误也会产生新版本、令旧产物过期 | 所有无副作用校验前置；提交失败时区分“仅保存成功”和“任务已提交” |
| P1 | 分镜图和黑白动作预演共用黑白提示语 | `workflow-production-workbench.tsx` 图片 prompt 组装 | 分镜图被错误限定为黑白预演风格 | 按 `storyboard` / `previz` 分别组装提示语并加纯函数测试 |
| P1 | 图片阶段的产物元数据和预览摘要仍显示视频分辨率 | 同文件 `artifactMetadata` 与预览摘要 | 产物规格展示与真实请求不一致 | 图片记录画质，视频记录分辨率；摘要按能力显示 |
| P1 | 工作流步骤一旦为失败态，前端直接拒绝重试；后端实际允许 `failed → ready/running` | `workflow-production-workbench.tsx` 与后端 `canTransitionWorkflowStep` | 某阶段失败后无法再次生成 | 重试前把失败步骤恢复为 `ready`，保持现有后端状态机 |
| P1 | 生成任务失败只显示“可重试”，真实安全错误原因不可见 | `workflow-production-workbench.tsx` | 用户无法判断模型、参考图或协议问题 | 在产物区显示规范化失败原因与重试入口 |
| P1 | 章节画布创建成功但章节关联失败时停留原页 | `detail.tsx` 关联异常分支直接 `return` | 已创建画布难以发现，后续关联路径不清楚 | 明确提示部分成功并继续打开画布 |
| P1 | 制作流程的“剧情与章节”直接渲染持久化 HTML 字符串 | `workflow-stage-views.tsx` | 用户看到 `<p>`、`<br>` 等标签 | 使用可测试的纯文本投影，保留段落和列表顺序 |
| P1 | 资产、画布和分镜侧栏请求失败时落入“空列表”表现 | `assets.tsx`、`canvases.tsx`、`workflow-production-workbench.tsx` | 用户误以为数据被清空 | 增加明确错误态、重试入口，保留已有数据时不闪空 |
| P1 | AI 创建流程先创建项目再请求模型；模型或 JSON 解析失败会留下无提示的空项目 | `pages/projects/index.tsx` `generateStory` | 项目列表出现孤儿项目，用户不知道如何继续 | 先生成并校验章节，再创建项目；导入失败时导航到已创建项目并明确提示可继续 |
| P2 | 不可见的待确认角色分页仍会请求 | `assets.tsx` candidates query | 大项目额外请求与渲染压力 | 按当前文件夹和分类启用查询 |
| P2 | 基线专项测试断言仍要求旧的两参数调用形式 | `test/project-chapter-skill-runtime.test.ts` | 基线专项套件红灯 | 更新为验证当前含对白上下文的三参数调用 |

## 实施前后对照

| 用户路径 | 实施前 | 实施后 |
| --- | --- | --- |
| 章节与镜头编辑 | 未保存内容只存在组件内存，刷新或离开可能丢失 | 用户隔离的 IndexedDB 草稿、自动恢复、离开保护；保存只清理对应快照，保存中的新编辑继续保留 |
| 章节任务恢复 | 可能用当前章节上下文物化其他章节任务 | 只恢复当前已加载章节；切到目标章节后再继续恢复 |
| 镜头生成提交 | 先保存镜头，再发现模型或参数不可用 | 模型、兼容性、参数与技能准备校验全部前置；保存成功但任务提交失败时明确告知部分成功 |
| 分镜/预演/视频语义 | 图片和动作预演共用黑白约束，规格摘要混用视频分辨率 | 分镜保持项目视觉语义，预演明确黑白节拍，视频保留对白与接戏；图片显示画质、视频显示分辨率 |
| 失败恢复 | 失败工作流步骤被前端永久拒绝，任务原因不可见 | 按后端既有状态机恢复为 `ready` 后重试，并显示规范化失败原因 |
| AI 创建项目 | 模型或 JSON 失败后可能留下空项目 | 先生成并校验，再创建和导入；导入失败则进入已创建项目并提示继续处理 |
| 资产与画布 | 请求失败像空数据；待确认角色默认不易发现；画布关联失败后停在原页 | 错误态和重试明确；默认全量视图可见候选；关联部分失败仍打开已创建画布 |
| 章节展示 | 制作流程可能直接显示 HTML 标签 | 统一转换为保留段落、换行和列表顺序的纯文本 |

## 遗留项与待用户确认

1. `delivery` 阶段仍只有检查视图，后端打包能力尚未接入；这是现有产品缺口，不在本轮前端正确性修复中扩展协议。
2. 真实文本、图片、动作预演和视频模型的端到端生成会产生费用，本轮没有触发；需要用户明确确认模型、渠道和预算后再验收。
3. 浏览器回归使用已有空项目且不写用户数据，因此没有在浏览器中实际保存章节、确认角色或提交生成；这些状态转换由专项测试、类型检查和后端测试覆盖。
4. 前端完整套件的导演台模板接线断言需要由对应画布任务更新测试锚点；它在审计基线已存在，未混入短剧修复提交。
