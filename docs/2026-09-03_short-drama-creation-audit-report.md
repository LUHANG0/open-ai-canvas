# 短剧创作全链路审计与优化报告

> 审计基线：`a855fa6`。独立分支：`refactor/short-drama-creation-audit-20260903`。基线标签：`audit/short-drama-creation-base-a855fa6`。阶段 11 起已快进集成到目标分支，最终验收完成后独立分支同步到同一提交，两个入口都保留完整回滚历史。
>
> 所有结论以当前分支代码、测试或运行验证为依据；不包含付费生成、真实计费配置修改或用户数据删除。

## 当前结论

短剧项目已经具备“项目 → 章节 → 角色与资产 → 分镜脚本 → 图片/动作预演/视频 → 交付与画布”的主体链路。本轮已修复审计中发现的数据丢失风险、跨章节错误恢复、生成前副作用、阶段提示语错配、失败步骤不可重试和部分成功不可达等问题；列表、空态、错误态和 PC 主路径也完成了非破坏性浏览器回归。在此基础上，继续完成了分镜制作工作台、章节编辑页和项目入口页的职责拆分，并在拆分后复核中修正了等值轮询重载镜头编辑器、项目创建投影模块越权写入和画幅下拉误改内容来源状态三个边界问题。页面保留流程编排，新模块只承接展示、纯状态投影与草稿生命周期。视频阶段现可一次提交所有缺少已选中视频、且没有运行任务的已保存镜头，提交前统一做模型兼容与费用确认，最多并发创建 3 个独立任务。交付阶段同时具备服务器后台与浏览器本机两条闭环：后台任务冻结镜头版本后持久执行、流式下载并在 7 天后自动回收，不进入模型计费队列；本机模式继续按设备能力核对源视频容量，超限会在 FFmpeg 合成前停止。真实模型生成与计费路径按约束保留为待用户确认项。

## 范围与边界

本轮实施最初覆盖 `web/src/pages/projects/`、项目 API 客户端、项目与画布衔接及相关前端测试；阶段 16 为五类资产拆分补充了后端提示词契约，阶段 18 又新增了后台异步交付 API、Repository、Worker、资源配额与 FFmpeg 运行依赖，阶段 19 将数据库 Schema 从 v4 升级到 v5 并增加 `project_delivery_jobs` 表。Admin、权限、模型计费和既有生成协议未修改；所有后端、数据库、Docker 与 CI 变化均在阶段记录和回滚表中单独列出。

不执行以下操作：

- 不触发真实图片、视频或文本付费生成。
- 不删除真实用户项目、章节、素材或产物。
- 不修改真实模型渠道、积分价格或权限；部署代码仅补充后台交付所需的 FFmpeg/ffprobe 依赖与发布门禁，不直接改写运行中的服务器配置。
- 不对移动端做视觉重构，只验证 PC 样式没有泄漏到小屏规则。

## 真实链路

| 阶段 | 页面与入口 | 主要读取 | 主要写入 | 恢复机制 |
| --- | --- | --- | --- | --- |
| 项目入口 | `/projects`、首页快捷入口 | 分页项目摘要 | 创建项目、AI 章节导入 | React Query 列表刷新 |
| 项目概览 | `/projects/:id/overview` | 项目核心、章节摘要、聚合指标 | 无 | 路由重载 |

## 首轮问题清单

| 优先级 | 发现 | 证据路径 | 用户影响 | 处理策略 |
| --- | --- | --- | --- | --- |
| P0 | 章节正文和镜头脚本刷新后丢失未保存修改，跨路由离开也没有统一保护 | `pages/projects/detail/chapters.tsx`、`workflow-production-workbench.tsx` 仅维护组件内 `dirty` | 长剧本编辑可能直接丢失 | 增加用户隔离的 IndexedDB 草稿、刷新恢复、保存后清理与路由/关闭保护 |
| P0 | 任务恢复遍历整个项目的完成任务，却使用当前已加载章节的资产与镜头快照物化结果 | `chapters.tsx` 恢复 effect 与 `storeGeneratedStoryboard` 闭包 | 切换章节后可能丢资产引用或出现错误替换冲突 | 恢复只处理当前已加载章节；打开目标章节时继续恢复 |
| P0 | 生成按钮先保存镜头版本，再校验模型渠道是否完整 | `workflow-production-workbench.tsx` 的 `generateArtifact` | 配置错误也会产生新版本、令旧产物过期 | 所有无副作用校验前置；提交失败时区分“仅保存成功”和“任务已提交” |
| P1 | 分镜图和黑白动作预演共用黑白提示语 | `workflow-production-workbench.tsx` 图片 prompt 组装 | 分镜图被错误限定为黑白预演风格 | 按 `storyboard` / `previz` 分别组装提示语并加纯函数测试 |
| P1 | 图片阶段的产物元数据和预览摘要仍显示视频分辨率 | 同文件 `artifactMetadata` 与预览摘要 | 产物规格展示与真实请求不一致 | 图片记录画质，视频记录分辨率；摘要按能力显示 |
| P1 | 工作流步骤一旦为失败态，前端直接拒绝重试；后端实际允许 `failed → ready/running` | `workflow-production-workbench.tsx` 与后端 `canTransitionWorkflowStep` | 某阶段失败后无法再次生成 | 重试前把失败步骤恢复为 `ready`，保持现有后端状态机 |
| P1 | 生成任务失败只显示“可重试”，真实安全错误原因不可见 | `workflow-production-workbench.tsx` | 用户无法判断模型、参考图或协议问题 | 在产物区显示规范化失败原因与重试入口 |
| P1 | 章节画布创建成功但章节关联失败时停留原页 | `detail.tsx` 关联异常分支直接 `return` | 已创建画布难以发现，后续关联路径不清楚 | 明确提示部分成功并继续打开画布 |
| P1 | 制作流程的“剧情与章节”直接渲染持久化 HTML 字符串 | `workflow-stage-views.tsx` | 用户看到 `<p>`、`<br>` 等标签 | 使用可测试的纯文本投影，保留段落和列表顺序 |
| P1 | 资产、画布和分镜侧栏请求失败时落入“空列表”表现 | `assets.tsx`、`canvases.tsx`、`workflow-production-workbench.tsx` | 用户误以为数据被清空 | 增加明确错误态、重试入口，保留已有数据时不闪空 |
| P1 | AI 创建流程先创建项目再请求模型；模型或 JSON 解析失败会留下无提示的空项目 | `pages/projects/index.tsx` `generateStory` | 项目列表出现孤儿项目，用户不知道如何继续 | 先生成并校验章节，再创建项目；导入失败时导航到已创建项目并明确提示可继续 |
| P2 | 不可见的待确认角色分页仍会请求 | `assets.tsx` candidates query | 大项目额外请求与渲染压力 | 按当前文件夹和分类启用查询 |
| P2 | 基线专项测试断言仍要求旧的两参数调用形式 | `test/project-chapter-skill-runtime.test.ts` | 基线专项套件红灯 | 更新为验证当前含对白上下文的三参数调用 |

## 复核结论与停止点

| Evidence | Finding | Path | 修复与门禁 |
| --- | --- | --- | --- |
| `useWorkflowShotDraft` 的装载 effect 直接依赖 `serverValues` 对象；工作区刷新会重新构造引用上下文和表单值，即使字段完全相同也会获得新对象 | 等值任务轮询可能再次执行 `form.setFieldsValue`，覆盖用户正在输入的镜头脚本 | 项目轮询刷新 → 新 `detail`/引用数组 → 新 `serverValues` 对象 → 草稿装载 effect → 表单重置 | `shotEditorValuesKey` 按固定字段顺序生成稳定快照；测试验证等值对象同键、字段变化异键，并锁定 hook 依赖快照键 |
| `project-story-generation.ts` 直接导入并调用 `createProject`；`aspectRatio` 表单项的 `onChange` 调用了 `setCreateSource` | 纯投影模块承担业务写入；用户修改画幅会把内容来源状态写成 `9:16/16:9/1:1`，造成按钮选中态和后续表单初始化错位 | 画幅下拉 → `setCreateSource(画幅)` → 非法来源状态；AI 解析模块 → 项目 API 写入 | API 重试回到页面协调器；投影模块只输出重名候选/冲突判断；内容来源下拉独立更新 `createSource`；源码交互门禁验证两个表单块不再串线 |
| 隔离浏览器中，章节没有任何镜头时从“视频生成”切到“剧情与章节”仍出现“离开未保存的镜头脚本？” | 空分镜工作区把“没有镜头版本”误当成编辑器脏数据，阻断正常阶段导航 | 无 `selectedShot` → `revision` 为空 → 初始化直接令 `editorDirty=true` → `useBlocker` 拦截路由 | 初始脏状态同时要求存在 `selectedShot`；源码门禁锁定条件；同一浏览器会话热更新后阶段导航直接到达 `/story`，不再弹窗 |

复核后达到合理停止点，依据如下：

- 所有新拆分的展示/投影模块均未直接发起项目、章节、镜头或生成任务写请求；资源 URL 解析仅用于展示。
- 镜头生成的“校验 → 技能准备 → 工作流初始化/恢复 → 保存镜头 → 提交任务 → 部分失败提示”和章节任务恢复仍完整保留在协调器，没有为降低行数而抽象事务。
- 章节编辑仅在章节 ID 变化时重新装载服务端正文；镜头编辑改用字段快照键；没有发现另一条由普通轮询对象身份触发的编辑覆盖路径。
- TypeScript、27 文件专项 128 项、快速预检 34 项和生产构建全部通过；构建为 13,639 个模块，仅有 chunk-size 提示。
- 交付已有后台异步与本机两条闭环；后台任务不进入模型计费队列。隔离发布镜像已使用 H.264/AAC MP4 与不同尺寸、无音轨 VP9 WebM 跑通规格统一、重启接管、206 Range、中文 ZIP、字幕/CSV 和到期物理回收；真实长章节的磁盘峰值、主流播放器声画质量及对象存储大文件下载仍需专门验收。真实付费模型验收也需单独评估资源、协议或费用边界。

## 实施前后对照

| 用户路径 | 实施前 | 实施后 |
| --- | --- | --- |
| 章节与镜头编辑 | 未保存内容只存在组件内存，刷新或离开可能丢失 | 用户隔离的 IndexedDB 草稿、自动恢复、离开保护；保存只清理对应快照，保存中的新编辑继续保留 |
| 章节任务恢复 | 可能用当前章节上下文物化其他章节任务 | 只恢复当前已加载章节；切到目标章节后再继续恢复 |
| 镜头生成提交 | 先保存镜头，再发现模型或参数不可用 | 模型、兼容性、参数与技能准备校验全部前置；保存成功但任务提交失败时明确告知部分成功 |
| 分镜/预演/视频语义 | 图片和动作预演共用黑白约束，规格摘要混用视频分辨率 | 分镜保持项目视觉语义，预演明确黑白节拍，视频保留对白与接戏；图片显示画质、视频显示分辨率 |
| 失败恢复 | 失败工作流步骤被前端永久拒绝，任务原因不可见 | 按后端既有状态机恢复为 `ready` 后重试，并显示规范化失败原因 |
| AI 创建项目 | 模型或 JSON 失败后可能留下空项目 | 先生成并校验，再创建和导入；导入失败则进入已创建项目并提示继续处理 |

| 章节展示 | 制作流程可能直接显示 HTML 标签 | 统一转换为保留段落、换行和列表顺序的纯文本 |
