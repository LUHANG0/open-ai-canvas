### 录制输入失败的分类与保留边界

首次继承的生产媒体探针在现场 MediaRecorder 录制后报“视频编码失败”。原探针仅在成功时记录结果，失败后浏览器在 finally 中关闭，原始 Blob 未落盘；原错误日志保留，但无法追溯或重放第一次的同一输入，不能声称根因已经关闭。

随后给同一录制流程增加编码前落盘，捕获另一组同错误样本：两份 WebM 均为 **0 字节**，SHA-256 均为 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`。FFprobe 和 FFmpeg 解码均退出 1（EBML header parsing failed / Invalid data）；同一空文件再次进入原产品编码函数，复现同样错误。该次 Worker/core/WASM 均为 200，可排除静态资产未加载；其失败发生在无效录制输入条件，不能将其计入有效媒体导出通过率。

本地探针补充首帧绘制、显式 requestFrame 和非空前置检查后，得到 11853/11943 字节的有效 VP8 + Opus 文件（96×54、48kHz 双声道）。两份文件分别为 `105a63731fa6b4d8fdfd6ea4725a653edcdad6b7c68be2bc88155806e90322c1`、`6edb905632f427a3e1b10b87c1171d8a4d3d2921162a95c3a818a29fe793e386`；FFmpeg 完整解码退出 0、stderr 为空。保留文件再次通过 WASM 取消/重试和有声 MP4 导出：23668 字节、1.325333 秒，音频 RMS 0.13963。中间尝试等待 MediaRecorder start 事件曾使探针等待，已停止该自建进程并改为显式采帧；没有把探针中断计为产品失败或成功。

结论分开记录：新捕获的空样本确认是录制夹具没有产出有效媒体；第一次相似失败由于输入缺失，只能推测同类原因。未观察到有效保留样本稳定复现的产品编码故障，因此没有据此修改业务代码。这个结果支持继续本地候选检查，不支持宣称完整录制链路已具备全量放行证据；真实录制、触屏/IME、其他浏览器与长媒体仍需受控验收及发布指挥评估。

独立音轨仍仅编排，预览/导出保留视频原声；字幕烧录失败会明确回退。不能宣传完整多轨混音、完整字幕交付或精确声画同步质量已经验证。
