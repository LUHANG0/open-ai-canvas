# PC 用户端视觉与交互规范

## 1. 页面类型

### 标准业务页

适用于 Home、Tasks、Assets、Skills、Wallet、Plugins、Settings、Projects、Canvas 列表。

统一结构：页面标题与上下文、主操作、筛选工具栏、内容表面、批量操作、分页、完整状态反馈。

### 沉浸式工作台

适用于 Create、项目工作流、Canvas 编辑器。允许全宽和高密度工具，但仍使用统一 Token、按钮、输入框、弹窗、状态和焦点规则。

### 全屏品牌/状态页

适用于登录、注册、公开分享、404、路由错误。可以有独立构图，不能建立另一套表单和状态样式。

## 2. 页面细则

- 页面标题只出现一次；面包屑、Eyebrow 和标题层级保持稳定。
- 每页最多一个视觉主操作；持久选中态不得使用 Primary Button 冒充。
- 搜索、筛选、排序、视图切换放入统一工具栏，并在窄 PC 宽度下允许换行而非裁切。
- 空态分为“无数据”和“筛选无结果”，文案及操作不同。
- 错误必须说明对象、原因和恢复动作，不能只显示 Toast。
- 表单使用分区标题、说明、字段和底部动作；危险操作单独成区。
- 二级导航统一使用 `SubnavLayout`，不再由 Plugins 和 Settings 分别实现。
- 媒体明确 `cover` 或 `contain`；素材默认 4:3，视频默认 16:9。
- 上传状态统一为空闲、拖入、校验失败、上传中、成功、失败、重试。

## 3. PC 验收视口

核心验收：1280×800、1440×900、1600×1000、1920×1080；1024px 作为下限兼容检查。

移动端只做“不因 PC 改动产生新增回归”的保护性检查，不纳入本阶段视觉重构验收。

## 4. 禁止项

- 不修改 `/admin/**`、`admin-ui.css`、后端、数据库、API 合同、权限和业务规则。
- 页面不得新增 `.admin-*` 依赖。
- 页面不得直接覆盖全局 AntD 类；通过主题或统一 `rootClassName` 处理浮层。
- 不用新的 `!important` 解决层叠冲突，除非记录原因并经 Foundation owner 审核。
- 不改变路由、查询参数、分页、轮询、上传、任务恢复和本地同步语义。
