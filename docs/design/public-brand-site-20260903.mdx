# 公开品牌官网与内容发布

## 目标

将原本直接跳入创作台的根路径升级为完整品牌官网，同时保持登录后的创作、项目、画布和管理后台路径稳定。公开内容必须可由管理员维护，但未经发布的编辑不能泄漏给访客。

## 页面与边界

| 路径 | 作用 | 访问边界 |
| --- | --- | --- |
| `/` | 品牌首页、产品总览、流程、作品与创作入口 | 公开 |
| `/product` | 创作对话、短剧生产、导演画布、同步与部署能力 | 公开 |
| `/showcase` | 可配置作品与 B 站等外部链接 | 公开 |
| `/about` | 产品理念、数据自主、部署与开源说明 | 公开 |
| `/login`、`/register` | 品牌认证入口 | 公开 |
| `/create`、`/home`、`/projects`、`/canvas` | 原工作台与业务数据 | 登录后 |
| `/admin/settings/public-site` | 官网草稿、作品、链接、SEO 与发布 | 管理员 |

公开官网使用独立布局，不挂载工作台侧栏。登录用户点击主按钮直接回到 `/create`，未登录用户通过带 `next=/create` 的登录路径进入。`/home` 同步补上登录保护，避免新的公开根路径引入未授权工作台入口。

## 配置模型

官网内容继续使用已有 `system_settings`，键为 `platform_public_site`，不新增表或数据库迁移。配置包含：

- Hero 文案、主次按钮、背景视频、海报与片场标识；
- 产品、流程、作品、关于四组章节文案；
- 最多 8 个公开作品的标题、分类、说明、封面、视频和外部链接；
- 文档、仓库、部署、联系、备案和搜索摘要。

记录同时保存 `draft` 与 `published`。管理员 PATCH 只更新草稿；发布动作才将草稿复制为线上版本。所有写入使用期望修订号做 CAS，旧页面不能覆盖新修订；保存、发布和重置均写入管理审计。公开接口只返回 `published`，并提供 ETag。

视频 URL 留空时，首页复用“品牌与外观”中的登录页背景和海报。桌面正常动态偏好下播放静音循环视频；移动端、减少动态效果、视频错误时显示海报或内置电影感渐变。

## API

- `GET /api/public/site`：读取已发布官网内容，不需要登录；
- `GET /api/admin/settings/public-site`：读取草稿与发布状态；
- `PATCH /api/admin/settings/public-site`：保存草稿；
- `POST /api/admin/settings/public-site/publish`：发布当前草稿；
- `POST /api/admin/settings/public-site/reset`：只把草稿恢复默认，不影响线上内容。

外部链接仅接受完整 `https://` 地址，站内链接接受单斜杠开头的路径；拒绝协议相对链接、带用户凭据的链接和脚本协议。

## 部署与回滚

本轮本地部署继续使用 `.local/project-workbench-debug` 数据目录，只替换应用构建，不移动、不清空数据库和资源目录。代码回滚以本功能独立提交为单位：回退该提交后，已存在的 `platform_public_site` 设置行会成为未使用数据，不影响账号、项目、资产、对话或其他品牌设置；重新应用提交即可继续读取。

如果只需回滚线上文案，可在后台把草稿改回原内容并重新发布，无需回滚应用。重置操作只处理草稿，因此不会意外改变访客正在查看的版本。
