# 短剧创作 PC 端设计规范

> 适用范围：`/projects` 项目入口、列表、创建流程，以及 `/projects/:projectId/**` 的公共页面框架。基线提交：`7f98cbb34a4e4ca53ccbfe02609bf18be07aa4a6`。

## 1. 边界与审计结论

### 1.1 不变的业务合同

- 路由、功能开关和权限继续由 `router.tsx` 与 `RequireFeature` 控制。
- 列表继续使用 `listProjects({ page, pageSize: 50 })` 和 `['projects', 'paged']` 缓存键，保留无限加载、重试和已加载计数。
- AI 创建继续按“生成故事 → 创建项目 → 导入章节 → 进入概览”执行，保留部分成功时的降级提示。
- 手动创建继续使用 `createProject`；小说或文本来源创建后进入章节导入，空白项目进入概览。
- 删除、画风选择、模型选择、项目状态、章节记忆与画布创建的调用和返回处理不变。

### 1.2 现状问题

| 区域 | 现状 | 本次方向 |
| --- | --- | --- |
| 页头 | 标题、总数与创建按钮可用，但对“正在做什么”的提示弱 | 增加精简的制作总览，保持一个主操作 |
| 创建入口 | 来源、模型、创建方式和 7 个参数同时平铺 | 先输入故事，再在清晰分区中调整参数；手动来源保持随时可达 |
| 项目筛选 | 搜索与两个下拉可用，状态识别成本偏高 | 状态使用带数量的持久切换，排序仍保留下拉 |
| 项目卡片 | 封面、阶段、进度和计数完整，说明文本利用不足 | 补充故事摘要和更新时间，将删除保留为次级悬浮操作 |
| 项目公共壳 | 项目名称、状态、六个视图和创建画布已在顶栏 | 建立稳定的项目身份区、导航区和上下文操作区，不改变各工作区内部 |

## 2. 信息架构

### 2.1 项目中心

PC 顺序固定为：

1. 页面身份：“短剧项目”、用途说明、已读取数量和“创建项目”主操作。
2. 制作总览：全部、进行中、已归档和平均章节完成度，数据均由已加载列表派生。
3. 创建工作台：一句话故事为主输入；模型和 AI 生成为主任务；空白、小说、文本和画风为可随时进入的次任务。
4. 项目库：标题与结果数、搜索、状态、排序、卡片结果和加载状态。

### 2.2 项目公共壳

- 左侧：返回项目中心、项目识别图形、项目名和状态。
- 中部：制作概览、剧情章节、分镜制作、项目画布、角色与资产、项目设置。
- 右侧：当前视图的主要上下文操作；分镜视图继续显示章节导航，其他视图继续显示新建画布。
- 公共壳只负责导航和状态语境，不改变章节、资产、分镜与生产工作区的数据和交互。

## 3. 视觉合同

### 3.1 Token

- 只消费 `docs/ui-design-system.md` 定义的 `--app-*` 语义 Token；不引用 `--admin-*` 或 `.admin-*`。
- 页面背景使用 `--app-bg-page`，主表面使用 `--app-surface-1`，次级分区使用 `--app-surface-2`。
- 主命令使用 `--app-action-primary-*`，持久选中使用 `--app-selection-*`，二者不混用。
- 字号限定在 11/12/13/14/16/20/24px 层级；数量、时间和进度使用等宽数字。

### 3.2 间距、圆角与层次

- 页面主间距 24px，卡片网格 18px，控件间距 8–12px。
- 控件高度 32/36/42px；控件圆角 8px，普通表面 12px，媒体卡片 14px。
- 以细边框和低阴影区分层次；悬浮只上移 1px，减少动效模式下取消位移。

## 4. 组件与状态

### 4.1 筛选

- 搜索、状态和排序必须始终具有可见标签或可访问名称。
- 状态切换使用 `aria-pressed`，按钮内显示当前已加载数量。
- 任一筛选生效时显示“重置”；结果数与筛选后数组一致。

### 4.2 项目卡片

- 整卡进入项目概览，删除为卡内独立按钮，必须阻止导航并继续弹出二次确认。
- 信息顺序：封面/阶段 → 名称/状态 → 摘要 → 画风/来源 → 章节进度 → 章节、画布、资产计数与更新时间。
- 进度使用原生 `progress`，持续保留可访问名称。

### 4.3 创建对话框

- 顺序为“选择来源 → 填写项目基础信息 → 可选画风 → 确认创建”。
- 来源卡必须使用 `aria-pressed`；不用主按钮颜色表达选中。
- 提交期间禁用重复提交，错误仍通过现有 `App.message` 呈现。

### 4.4 加载、空态与错误

- 首次加载、首次失败和空结果继续由 `WorkspaceLoadingState` / `WorkspaceErrorState` / `WorkspaceState` 呈现。
- 首次失败必须有重试；空项目必须有空白项目和导入小说两个可行入口。
- 后续页加载失败在列表末尾就地重试，不覆盖已有项目。

## 5. 响应式和可访问性

- 本规范仅在 `min-width: 1024px` 生效；新增 PC 辅助内容在断点之前隐藏，不改变现有移动端输出。
- 可交互元素保留 `:focus-visible`，图标按钮必须有 `aria-label`。
- 持久选中使用 `aria-pressed` 或 `aria-current`；加载文案和列表末尾状态使用 `aria-live` 但不反复抢占焦点。
- 关键操作不仅依赖悬浮；卡片可聚焦，删除按钮在键盘聚焦时可见。
