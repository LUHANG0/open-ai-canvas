# 前端 UI 技术栈收敛记录（2026-09-03）

## 目标

在不修改接口、数据、权限和页面业务流程的前提下，逐批减少并行 UI 实现，形成可持续的公共组件边界。首批只处理空、加载、错误状态组件，视觉与交互合同保持不变。

## 基线与范围

- 开始基线：`9192418`。
- 分支：`release/v1.2.2-preview.3-rc-20260903`。
- 涉及：用户端公共 UI、页面导入路径、对应静态回归门禁和设计系统文档。
- 不涉及：Admin、后端、数据库、接口、账号数据、品牌设置、计费与真实生成。

## 首批决策

1. `web/src/components/ui/pc/workspace-state.tsx` 是通用状态组件的唯一实现位置。
2. 页面统一使用 `WorkspaceState`、`WorkspaceLoadingState`、`WorkspaceErrorState`；原 `components/layout/workspace-state.tsx` 被移除。
3. 删除未被页面使用的第二套 `EmptyState` 与对应 112 行样式，避免后续继续分叉。
4. 画布、创作等包含业务引导动作的专属空态继续保留，不强行抽象为通用组件。
5. Ant Design 继续承担复杂控件，项目公共组件承担品牌化中性结构，Tailwind/页面 CSS 只做布局与局部编排。

## 第二批：页面骨架边界

1. 将 `WorkspacePage`、`PageHeader`、`ListToolbar`、`TableSurface`、`CollectionGrid`、`PaginationBar` 整体迁入 `web/src/components/ui/pc/page.tsx`。
2. 用户端 16 个直接依赖入口切换到公共 UI 层；组件 DOM、类名、筛选展开和分页算法均保持不变。
3. `web/src/components/layout/workspace-page.tsx` 缩为兼容转发层，只供现有 Admin 页面使用；本批不修改 Admin 文件和样式。
4. 公共组件 Props 改为显式导出类型，后续页面扩展不再从组件实现反推合同。
5. 静态门禁要求所有非 Admin 代码不得重新依赖旧 layout 路径，并检查兼容文件不再承载实现。
6. 页面与集合组件采用同一显式子路径导入，不从 `ui/pc` 总 barrel 再导出，也不拆成多个物理模块；完整构建曾检测到拆分模块改变分包归属并导致画布、创作首访预算超限，因此在提交前恢复单一共享模块。

## 第三批：任务操作区

1. 不新增全局 Button 包装层；普通业务操作继续使用 Ant Design，避免技术栈再次分叉。
2. 任务网格卡和列表行原来各自维护查看、失败重试、内容审核禁重试和 loading 判断，现统一由任务域内 `TaskActions` 负责。
3. 两种视图继续保留各自外层操作区、卡片结构与 CSS 类名，只复用完全相同的按钮合同和判断逻辑。
4. 新增专项静态门禁，要求两种视图都消费共享操作组件，按钮可访问名称、审核限制和任务级 loading 不得丢失。
5. 卡片审计确认项目卡、素材卡、技能卡、画布节点和影视工作台承担不同点击面与交互语义，本批不强行替换为单一 Card 组件。

## 第四批：素材路径导航

1. Eagle 素材库与项目素材页原来分别维护同一套根目录、多级路径、分隔符和文件夹跳转按钮，现统一使用中性 `PathBreadcrumb`。
2. 组件只接收路径项和点击回调，不读取素材 Store、插件状态或项目接口；Eagle 与项目素材的数据、选择和创建逻辑保持原归属。
3. 保留原按钮类名、字号、间距和 hover 表现，项目素材路径从普通 `div` 补充为带明确名称的 `nav`，分隔符统一对辅助技术隐藏。
4. 新增专项静态门禁，防止两个入口重新复制路径按钮实现，并固定根目录与多级目录的键盘可操作合同。

## 第五批：资源库新增卡

1. 素材库与技能库原来分别复制 `library-create-card` 的封面、图标、标题和说明 DOM，现统一使用中性 `LibraryCreateCard`。
2. 公共组件只负责按钮结构和稳定类名，页面继续传入图标、文案与点击回调；素材创建、技能安装和权限判断均未迁入组件。
3. 两页既有 CSS 继续按页面作用域控制卡片比例、高度、网格和 hover，不把素材与技能卡强行改成同一视觉尺寸。
4. 新增专项静态门禁，要求两个入口消费共享结构，同时保留各自业务动作。

## 第六批：画布全屏加载态

1. 3D 导演台、节点编辑器与时间线工具原来分别维护全屏加载壳，现统一由画布域内 `CanvasWorkspaceLoadingOverlay` 承担。
2. 组件保留主题化画布背景和中性页面背景两种现有表现，文案、层级、居中布局和懒加载时机不变。
3. 导演台加载占位补齐 `status` 与 `aria-live` 语义，三类入口共享同一可访问性合同。
4. 该组件保持在画布页面私有边界，不与全站路由 `FullScreenLoader` 强行合并；两者主题上下文和遮罩语义不同。
5. 新增专项门禁，防止三个入口重新内联 `WorkspaceState` 全屏壳，并固定两种背景与状态语义。

## 第七批：画布弹窗加载遮罩

1. 分镜脚本、节点搜索、分享/导入、素材库、图片工具、任务/预览和上传/节点信息七个页面边界原来重复同一套半透明加载遮罩，现统一为 `CanvasDialogLoadingOverlay`。
2. 公共组件只接收加载文案和可选关闭回调，不接管各弹窗的开关、数据、提交或路由状态。
3. 原遮罩透明度、背景模糊、层级、提示卡样式、文案与懒加载时机均保持不变。
4. 节点搜索和分镜脚本继续提供加载期间的“关闭”逃生入口，其余弹窗继续使用纯状态提示。
5. 新增专项门禁，要求七个弹窗所有者都经共享边界渲染，不再内联该遮罩结构。

## 第八批：闲置上传与媒体基础组件

1. 全库引用审计确认 `UploadField`、`FileDropzone`、`UploadProgress`、`MediaFallback` 和 `MediaThumbnail` 仅存在于自身定义与 barrel 导出，没有产品调用方。
2. 真实素材上传、画布批量上传、创作参考与媒体预览具有不同的文件校验、进度、鉴权和失败回退合同，本批不将它们强制迁入无调用的通用外壳。
3. 删除两个闲置模块、barrel 导出和 459 行专属 CSS，代码批次合计减少 694 行实现；没有修改任何真实页面 DOM 或业务状态。
4. 构建后 PC 公共样式分包从约 33.78 kB 降至 23.09 kB，不影响全局 CSS 和其他业务分包。
5. 静态门禁现在禁止重新发布这两套无消费方的公共 API 与死样式；未来如需公共上传/媒体能力，应从真实业务合同提取。

## 第九批：画布内嵌面板加载态

1. 普通节点设置/配置编排与多角度/表情工作区原来分别维护同一套可关闭内嵌加载卡，现统一由 `CanvasInlinePanelLoading` 承担。
2. 组件只接收文案、最小高度、关闭回调和可选可访问名称；面板世界坐标、拖动偏移、懒加载与生成回调保持在原所有者。
3. 四类入口继续使用 190、303 和 350 像素的原最小高度，表面、字号、间距、遮罩和关闭文案不变。
4. 多角度和表情加载占位的关闭按钮现在与普通节点面板一样具有明确可访问名称。
5. 专项门禁要求两个页面所有者均经共享边界渲染，同时固定关闭语义和各类面板高度。

## 收尾审计与停止边界

1. PC 公共组件的导出与调用已逐项复核：`SelectionBar`、`StatTile`、`StatusBadge`、筛选组件、弹窗/抽屉框架、表单分区、页面表面、二级导航和工作区状态族均有真实业务调用；`pc-ui.css` 未发现静态孤儿选择器。
2. 画布剩余加载实现不再继续合并。工具栏设置和创建菜单绑定各自弹层尺寸与关闭语义，素材托盘绑定主题和动态高度，节点/多选工具栏绑定画布坐标与缩放，侧栏、短剧引导和空画布占位绑定独立布局，节点内容还承载真实任务进度、异常状态和详情入口，3D `LoadingBone` 则是场景视觉对象而非界面等待态。
3. 上传和媒体能力继续由素材、创作与画布业务入口分别持有，因为文件校验、鉴权、任务进度、重试和预览回退合同不同；只有出现至少两个完全相同的真实调用合同时，才重新提取公共组件。
4. 不新增全局 `Button`、`Card` 或第二套页面容器。普通控件继续由 Ant Design 承担，中性品牌结构放在 `components/ui/pc`，任务和画布等强业务交互留在领域目录。
5. 本轮结构收敛到此停止。后续 UI 工作转入真实浏览器、真实账号和多视口人工验收；在出现新的重复调用证据前，不再为“看起来相似”的结构增加抽象层。
6. 从基线到收尾共完成九个独立代码批次，涉及 51 个前端与记录文件，累计 684 行新增、1324 行删除，净减少 640 行；接口、数据库、账号数据、品牌设置和本地配置均未修改。

3. 服务仍直接读取仓库内既有 `.local/project-workbench-debug` 数据目录，使用 `CANVAS_AUTO_MIGRATE=false`，没有复制、重置或迁移账号、任务和品牌设置。
4. 验证通过：手动 `kickstart -k` 后服务自动恢复，后端直连、`127.0.0.1:8888` 代理和 `localhost:8888` 代理均返回 200；Schema 6/6、活动 Worker 为 0，数据库完整性为 `ok`，历史任务仍为 9 个成功和 6 个失败。
