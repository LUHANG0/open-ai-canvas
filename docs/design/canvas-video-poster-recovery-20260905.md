# 画布刷新后视频封面恢复

- 基线：`04964f3d`，确认继承 `origin/main`。
- 实施提交：`2c8478b4`；预览仍为 `3012`，本地实现完成，待用户验收。
- 范围：视频封面共享请求的订阅、取消与清理；不涉及后端或数据库迁移。

## 原因与修复

刷新列表后进入画布，实测 48 个视频节点中 40 个封面处于 `error`，8 个已有缓存的封面正常。失效发生在封面恢复流程；视频悬停预览使用另一条媒体加载流程。

封面生成任务按用户、素材与尺寸共享。最后一个订阅者退出时会取消底层任务，但任务完成前仍留在进行中列表。React StrictMode 的 effect 清理与重挂载，以及快速退出再进入，可能让新订阅者复用这个已取消的任务，得到空结果后一直停留在失败状态。

将共享请求生命周期隔离到 `canvas-video-poster-requests.ts` 进行独立验证：已取消任务不再复用；旧任务迟到完成时，仅清理自己，不能删掉替代任务；调用前已经取消的请求不创建新任务。多个有效订阅者仍共享一次生成，最后一个退出才取消底层任务。缓存键、封面格式、质量、并发队列与悬停播放合同保持原样。

## 验证

- 先保留原生命周期逻辑执行新回归测试，复现 4 项失败；修复后新增 6 项全部通过，覆盖立即重挂载、旧任务成功/失败回调迟到、共享订阅取消、预取消以及请求隔离与失败后重试。
- 封面请求、性能档位、首帧、悬停会话、播放入口、视频截帧与资源 URL 状态共 61 项测试、262 个断言通过，0 失败。
- `bun run build` 通过类型检查、生产构建和全部 7 项体积预算；画布首次进入新增 JS 为 837.7 KiB，预算 859.4 KiB。构建日志保存在忽略目录 `.local/cache/canvas-video-recovery-20260905/build.log`。
- Chrome 在现有本地画布复测「返回列表 → 刷新 → 打开画布」：48 个视频封面全部 `ready`，48 张图片完成解码。随后直接刷新画布，再次全部恢复；没有清除用户缓存。
- 悬停原来封面失败的首个视频，实际解码为 864×496、媒体就绪状态为 4，首帧覆盖层确认 `ready`，播放时间推进至约 10 秒；移开后播放器释放，48 个封面继续显示。自动化期间临时启用浏览器焦点模拟，验证后已关闭。
- 仅操作导航、刷新和视频预览，没有执行节点编辑、删除或生成。播放及刷新前后，原有 96 个节点的 ID 与内联位置、尺寸样式保持一致。

本次没有重新运行无关业务的全量测试。其他浏览器与生产环境按原发布流程验收；本地预览完成不代表已部署。
