# 大型画布交互性能优化与回滚记录

本轮减少拖动连线的图形重建、无关资源引用变化造成的节点渲染，以及调整尺寸时的全项目状态写入。改动限定于前端画布、专项验证和本文记录。

## 证据、问题与处理路径

| 代码证据 | 原问题 | 本轮处理 |
| --- | --- | --- |
| `canvas-leafer-graphics-layer.tsx` 原 `rebuildConnections` 每次 `removeAll(true)` | 拖动一条关联边也销毁重建全部可见连线 | 新增 `CanvasConnectionGraphics`，按连接 ID 复用对象；只更新变化的几何或样式；移除离屏/删除的边并销毁对象 |
| `use-canvas-render-model.ts` 与节点 props 引用比较 | 同一媒体档位仍创建新对象；悬停重新创建未变标签 | 档位复用冻结常量；未变化的引用对象、数组和 Map 保持引用；单独缓存影响资源引用的语义 |
| 普通节点与背板的原 `mousemove` 回调 | 调整尺寸时每次鼠标事件写整个节点数组，继而触发历史和保存准备 | 共享尺寸手势控制器与 hook，局部 rAF 预览，结束按最终坐标一次提交 |
| 全景浏览器命中检查：角点中心实际命中 `ConnectionSideRail` | 视觉外壳的 hover transform 创建堆叠上下文，内部尺寸角点被外部连线按钮覆盖 | 尺寸角点移到节点坐标层，与连线按钮同级并置于其上；保留远景键盘/交互限制 |
| `use-canvas-history.ts` 与 `canvas-node-timestamps.ts` | 未变化的数组和节点仍被重复扫描/解析 | 历史对同引用数组立即返回；未变节点跳过时间戳解析 |

资源快照保留原始标题判断，覆盖“空标题改为与全局默认编号相同的显式标题”场景，避免局部引用标题陈旧。真实生成输入仍使用最新节点和连接。

尺寸预览覆盖普通节点和背板，保留原始比例、最小尺寸、分镜最低高度和子节点边界。节点内容使用局部预览几何，视频画面随外框变化。Escape、撤销/重做快捷键在活动手势中仅取消预览，此次按键不同时执行已有历史的撤销/重做。失焦、指针取消、卸载和外部几何变更也会取消，不写回旧快照。

**交互取舍：调整尺寸期间，连线和小地图保持最后已提交的尺寸；松手后一起更新。** 普通位置拖动的连线仍实时跟随。

## 可复现验证

```sh
cd web
bun run typecheck
bun test test/canvas*.test.ts
CANVAS_PERF_REPORT=../.local/cache/canvas-performance-final.json bun scripts/canvas-p0-chrome-e2e.mjs
```

仅运行性能交互样本可设置 `CANVAS_PERF_ONLY=1`；再设置 `CANVAS_PERF_VIEW=overview` 可单独复现全景。脚本使用独立的 Vite、Chrome 进程与临时浏览器配置，不使用用户账号，不发起生成；本次验证结束后清理这些进程和配置。尺寸样本检查真实指针捕获、松手前的 DOM 预览、项目状态更新次数及最终结果，避免只保存成功而预览未工作的假通过。完整回归从 E 场景切入性能场景前，先等待夹具本地保存完成，避免自动切页触发未保存离页警告。

采样使用同一 324 节点、612 连线的文本夹具，1366×900、DPR 1；普通视图挂载 36 节点、72 连线，全景视图挂载 324 节点、612 连线。每种视图记录三次拖动及一次尺寸调整，每次发送 60 个指针移动事件，并包含结束后 900ms 的历史/保存工作。采集脚本耗时、布局耗时、帧间隔、长任务及项目状态更新次数。

`storeUpdates` 统计 Zustand 中 `projects` 引用发生变化的次数，不等于磁盘写入次数。`persisted` 表示界面的本地保存状态已完成；F 样本没有逐次重载回读。完整回归中的 C 场景另行验证位置和节点在刷新后保留。

环境为 Chrome headless、SwiftShader 软件图形后端与 Vite DEV。帧间隔受自动化输入节奏、软件绘制和本机调度影响，不能换算成用户设备的生产帧率或承诺固定 FPS。优先用同场景脚本耗时、状态写入次数和功能断言评估改动。

## 验证结果与原始证据

- TypeScript 类型检查通过。
- 画布相关测试：115 个文件，482 项通过，0 失败，共 1927 个断言。
- 完整 Chrome 回归：95 项通过，0 失败；包括拖动、历史、复制、搜索、面板、刷新恢复、紧凑视口、裁剪及本轮性能手势，最终运行未记录页面或网络错误。没有执行生产构建。
- 连线专项使用真实 Leafer Group/Path 对象：500 条独立连线中移动一个端点，仅重算 1 条路径，另 499 条没有重建、重新添加或设置属性。

基线保留原有失败，避免把无效手势当成更快的结果：普通尺寸调整能预览并保存，但单次撤销未恢复原尺寸；全景尺寸角点被连线操作区覆盖，未产生尺寸变化。后者的 CPU 数据不进入尺寸调整性能对比。全景单独调试的样本选择了另一节点，仅用于功能诊断；对照数据使用完整 detail → overview 序列中的相同节点。

| 指标 | 优化前 | 优化后 | 解释 |
| --- | ---: | ---: | --- |
| 普通视图拖动脚本耗时，3 次中位数 | 1792.88 ms | 1675.70 ms | 本次样本降低约 6.5%，幅度较小，需考虑本机波动 |
| 全景视图拖动脚本耗时，3 次中位数 | 2578.63 ms | 1831.51 ms | 本次样本降低约 29.0% |
| 普通视图尺寸调整脚本耗时，1 次 | 4352.20 ms | 429.67 ms | 相同目标与最终尺寸；本次样本降低约 90.1% |
| 普通视图尺寸调整项目状态更新 | 53 次，其中手势中 52 次 | 1 次，手势中 0 次 | 局部预览仍可见，松手统一提交 |
| 全景视图尺寸调整 | 角点误触连线，尺寸未变 | 可预览、1 次提交、1 次撤销恢复 | 旧手势无效，不计算耗时收益 |

原始数据：[优化前性能样本](evidence/canvas-performance-20260905/baseline.json)、[优化后完整回归与性能样本](evidence/canvas-performance-20260905/optimized.json)。基线只运行 F 性能场景，13 项断言中 10 项通过、3 项失败；优化后运行 A–F，含新增预览/取消断言共 95 项。两份报告的总断言数不能直接用来计算通过率提升。

用户随后授权了当前本地页面的直接操作验收，新增 24 项检查中 21 项通过、3 项未通过，发现大图刷新尺寸回退及相邻图形操作合并撤销两类既有问题。完整复现与边界见 [浏览器直接操作验收](canvas-live-validation-20260905.md)；此前 95 项通过不覆盖这两个新增场景。

本轮也修正了验证脚本的两个等待条件：切页前等待本地保存完成；首屏图片检查等待解码完成。前者避免自动化切页产生 `beforeunload` 警告，后者避免把正在加载的图片误判成失败；原有错误断言仍保留。

## 回滚步骤

以下操作在仓库根目录执行。先查看 `git status --short`；如有后续未记录的改动，先提交或另存，避免与回滚混在一起。

```sh
git status --short
git revert 34f4cffb
```

该命令新增一个撤销提交，只撤销本轮前端实现和测试，保留本文、原始证据和其他已有提交。它不删除画布项目、媒体或数据库；本轮也没有修改保存格式。交付前已检查实施补丁能够反向应用，未实际执行回滚。回滚后可按上面的类型检查和画布专项测试命令复验。

如只需查看优化前代码，可从 `canvas-performance-r0-20260905` 创建独立目录，不切换当前工作目录：

```sh
git worktree add --detach ../canvas-performance-r0-review canvas-performance-r0-20260905
```

`canvas-performance-r1-20260905` 保存优化后完整记录；本轮不执行历史重置或强制推送。

## 保留边界

- 每帧仍线性检查可见连线，渲染模型仍扫描全部节点/连线；尚未引入空间索引。
- 首次构建高扇入 Config 引用仍有平方级对象数量，后续无关进度/尺寸变化会复用引用快照。
- Config 输入与自定义节点内容的刷新路径保留，避免下游分镜进度不更新。
- 远景仍挂载视口内完整节点；没有统一的远景概要节点或原图缩略图生成改造。
- 本地保存与云同步仍有全项目处理；本轮通过减少尺寸调整提交次数降低触发频率，没有修改跨标签合并或生成结果持久化语义。
- 固定夹具不含大量真实视频与图片；真实媒体密集画布的性能、显存占用和长时间使用仍需单独验收。
