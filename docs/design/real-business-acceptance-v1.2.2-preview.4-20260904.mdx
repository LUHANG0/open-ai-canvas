# v1.2.2-preview.4 真实业务验收与 Go/No-Go 记录

## 结论

**当前整体结论：No-Go。** RC 的自动门禁、离线验证和零费用隔离业务链全部通过，未发现已确认的 P0/P1 产品缺陷；但真实目标环境、真实渠道、付费生成与计费、外部对象存储、维护窗口内运行中任务恢复尚未获得授权或输入，不能把本轮结果外推为生产可上线。

本轮可给出的精确判断是：

- **进入外部真实业务验收：Go。** 代码、构建、数据库迁移、权限、任务状态、SSE、存储、重启持久化及隔离恢复没有形成新的技术阻塞。
- **生产发布：No-Go。** 下文“未执行项”仍包含发布必测项；这些项通过前不得发布。

## 隔离业务链

本轮从本地 RC 源码构建 Backend/Web 候选镜像，OCI 元数据写入 `v1.2.2-preview.4`、完整 revision `f0618e42096c88c2d57efd7b96d350fd29fb6dec` 和提交时间。Compose 配置校验通过；生产镜像中的 Backend 运行时为 Go `1.25.14`，健康接口同时返回版本、revision 和 Schema。

经正式 Nginx 入口 `http://127.0.0.1:43124` 完成以下零费用链路：

1. 注册首位管理员，创建普通用户 B，并分别登录。
2. 管理员上传仓库内图片；认证 Range `bytes=0-15` 返回 `206`，16 字节 SHA-256 为 `02a3e298f1533f62558c58e4c70edcab9af5a50d62d925fd5390942020fb0fb8`。
3. 保存含图片引用的画布，并故意写入 `apiKey`、`taskId` 形态的秘密字段。用户 B 读取返回 `404`；匿名分享投影中对应字段数为 `0`。
4. 匿名分享资源 Range 返回 `206` 且哈希一致；撤销分享后画布与资源入口均返回 `404`。
5. 创建前端托管文本重放任务，渠道指向 `.invalid` 且不入队、不访问上游、不计费。SSE 首次返回 progress 和 `id: 1` delta，并带 `X-Accel-Buffering: no`；追加第二段并完成后，以 `Last-Event-ID: 1` 重连，只收到 `id: 2` 和 terminal。
6. 未登录访问任务返回 `401`，用户 B 访问他人任务返回 `404`，用户 B 访问管理员用户接口返回 `403`。
7. 重启 Backend 后，readiness 恢复为 true；登录、画布及成功任务仍可读取。

健康与版本结果：`/api/health/live`、`/api/health/ready`、`/api/system/version` 均返回 HTTP 200；`ready=true`、`started=true`、`draining=false`，database/runtime/schema 全部为 true，`currentSchemaVersion=expectedSchemaVersion=6`。`migrate-schema status` 和 `verify` 同样通过。

这条链验证了状态机、持久化、权限和 SSE 代理，但不等价于真实供应商任务执行，也没有产生费用。

## 观察项

### O-001：Canvas E2E 并行运行出现超时，串行不复现

同时运行 Canvas、Director 和 Delivery 三套 Chrome 时，Canvas 的搜索、复制/粘贴及其依赖断言出现 4 个超时，结果 `72/76`；释放并行浏览器负载后，原命令无修改重跑为 `76/76`。Director 与 Delivery 同轮保持全绿，浏览器问题列表为空。

判定为 P3 测试编排可靠性观察，不是已确认产品失败。发布门禁应继续串行运行三套浏览器 E2E；若串行再现则升级为阻断缺陷。

前端构建同时打印若干大于 500 kB 的 Vite chunk 提示，但仓库的 7 项 gzip 体积预算全部通过；最紧项目为最大 CSS `119.4/123.0 KiB`。这是容量余量观察，不构成本次失败。
