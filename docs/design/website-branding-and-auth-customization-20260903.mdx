# 网站品牌与登录页自定义化

## 交付状态

本轮采用“服务端单一配置源 + 前端运行时品牌 Provider + 管理后台编辑器”的方案。品牌名称、主题主色、Logo、浏览器图标、登录页背景和登录文案由管理员统一维护；登录、注册、工作台侧栏、首页、创作页、共享画布与注册验证码邮件读取同一份配置。

实现不新增数据库表或结构迁移。配置写入既有 `system_settings` 表的 `platform_branding` 键，资源沿用既有 `resources` 存储，管理动作写入 `admin_audit_events`。

## 管理入口与生效规则

入口：`/admin/settings/branding`。

- 文案与主题色在点击“保存修改”后整体生效。
- Logo、favicon、登录页背景和视频海报上传后立即生效。
- 页面带修订号并使用 Compare-And-Swap 保存；另一标签页先保存时，旧页面会收到冲突提示，不会静默覆盖。
- “恢复默认”会恢复影策默认文案、颜色和资源引用，同时保留历史上传资源，便于人工恢复。
- 登录页配置请求失败时使用浏览器上次成功缓存；没有缓存时使用内置默认品牌，品牌服务异常不会阻断登录。

## 配置范围

| 分组 | 字段或资源 | 当前消费入口 |
| --- | --- | --- |
| 品牌身份 | 展示名、简称、英文名、工作台名称、标语、描述 | 登录、侧栏、顶栏、首页、创作页、共享画布、注册邮件 |
| 主题 | `#RRGGBB` 主色 | 用户端 Ant Design 组件和品牌 CSS 色阶；管理后台继续使用稳定的后台主题 |
| 登录页 | 页眉、标题、描述、状态文案 | 登录与注册共用场景 |
| 浏览器 | 页面标题、Meta Description | 全站运行时 `<title>` 与描述 |
| 品牌资源 | Logo、favicon、登录背景、视频海报 | 全站品牌标记、浏览器图标、登录页视觉区域 |

技术标识不参与品牌替换，例如数据库键、IndexedDB 名称、剪贴板格式和 `infinite-canvas` 包名。这些字段属于兼容性协议，改名会导致旧数据或集成失效。

## 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/public/branding` | 公开 | 返回安全的品牌文案、主题和资源 URL；支持 ETag |
| `GET` | `/api/public/branding/assets/:slot` | 公开 | 只读取当前激活的品牌资源，支持 Range 与不可变缓存 |
| `GET` | `/api/admin/settings/branding` | 管理员 | 返回配置、修订号和资源引用 |
| `PATCH` | `/api/admin/settings/branding` | 管理员 | 按预期修订号保存文案和主题 |
| `POST` | `/api/admin/settings/branding/assets/:slot` | 管理员 | 上传并激活指定资源 |
| `DELETE` | `/api/admin/settings/branding/assets/:slot` | 管理员 | 清除指定资源引用 |
| `POST` | `/api/admin/settings/branding/reset` | 管理员 | 恢复内置默认配置 |

资源位置为 `logo`、`favicon`、`auth-hero` 和 `auth-hero-poster`。服务端按文件魔数识别 PNG、JPEG、WebP、GIF、MP4 和 WebM，不信任文件名或请求 MIME；Logo 和 favicon 不接受视频。大小上限分别为 2 MiB、512 KiB、40 MiB 和 8 MiB。SVG 暂不开放上传，避免主动内容进入公开资源端点。

## 变更记录

后端核心变更：

- `backend/internal/service/branding.go`：默认配置、校验、修订控制、资源激活、公开投影和审计。
- `backend/internal/handler/branding.go`：公开与管理接口、缓存头、上传限制。
- `backend/internal/repository/repository.go`：系统设置 Compare-And-Swap 与审计同事务写入。
- `backend/internal/service/admin_storage_delete.go`：阻止删除仍被品牌配置引用的资源。
- `backend/internal/service/email.go`：注册验证码主题、正文和默认发件名称跟随品牌。
- `backend/cmd/server/main.go`：注册品牌路由。

前端核心变更：

- `web/src/components/branding/`：品牌 Provider 和带失败降级的 BrandMark。
- `web/src/lib/branding-theme.ts`：主色规范化、色阶派生、CSS 变量和 Ant Design 覆盖。
- `web/src/pages/admin/settings/branding-settings-page.tsx`：后台编辑、预览、资源上传和恢复默认。
- `web/src/pages/auth/`：登录与注册共用设置请求、首管理员/关闭注册路由收敛、可配置背景和减少动态效果支持。
- `web/src/application.tsx`、工作区入口、首页、创作页和共享画布：接入统一品牌上下文。

## 回滚与恢复

优先使用配置回滚，不需要回退数据库结构：

1. 进入 `/admin/settings/branding`，点击“恢复默认”。这会创建新的修订和审计记录，不会删除旧资源。
2. 若只需撤销单个媒体资源，使用对应资源卡片的“移除”；其他品牌配置保持不变。
3. 若需恢复某次历史内容，在管理审计记录中查找 `branding.update`、`branding.asset.upload`、`branding.asset.clear` 或 `branding.reset`。审计元数据包含变更前后的配置和资源 ID，可据此重新填写或重新激活资源。
4. 若品牌接口暂时不可用，前端会自动使用最后成功缓存或内置默认值；先恢复后端服务，不必清理用户浏览器数据。
5. 若必须做代码级回滚，只回退“变更记录”列出的品牌相关文件和路由注册。不要回退同一工作区中独立完成的创作对话云同步、媒体存储或其他未提交变更。

历史资源为可回滚性而保留，会继续占用资源存储和上传配额。确认不再需要后，可在资源管理中清理未被当前品牌配置引用的文件；当前激活资源会被服务端拒绝删除。

## 自动验证

- 后端：默认读取、配置保存、修订冲突、恢复默认、审计数量、资源魔数与类型边界、公开接口 ETag/304。
- 前端：默认色阶、自定义色阶、管理后台主题隔离、Provider/登录页/管理路由接线，以及 TypeScript 类型检查。
- 生产构建：执行完整 Vite 构建和既有体积预算，确认新入口不会破坏发布产物。

仍需在真实浏览器完成 Logo/favicon 刷新、图片与视频登录背景、移动端/减少动态效果和双标签页并发保存的人工检查，清单同步记录在“待测试”。
