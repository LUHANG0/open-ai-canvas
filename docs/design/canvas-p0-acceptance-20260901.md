# 画布 P0 验收工程（2026-09-01）

## 范围

- 目标：为 PC 画布编辑器建立可重复、隔离、不会污染用户账号的真实浏览器验收链路。
- 工作分支：`test/canvas-p0-acceptance-20260901`。
- 基线：`a847e1e`；基线 Tag：`canvas-p0-acceptance-r0-20260901`。
- 禁止修改后端、Admin、数据库、API 合同、接口返回格式、权限、计费和业务规则。
- 验收不触发付费生成，不上传用户文件，不新增或删除用户账号内的画布。

## 第一阶段设计

1. 新增 DEV-only `/dev/canvas-repro/:id`，复用真实 `CanvasProjectPage`，生产构建通过 `import.meta.env.DEV` 摇树移除。
2. 临时 Chrome profile 首次打开时写入固定本地夹具；刷新后不重置，用于验证自动保存和恢复。
3. 夹具包含文本、图片和生成配置节点以及真实连接，媒体只使用 Vite 同源静态资源。
4. 浏览器 E2E 使用临时 Vite 端口、临时 Chrome profile 和 CDP；所有进程、端口和 profile 在结束时清理。
5. E2E 覆盖加载、节点渲染、选择、拖动、撤销/重做、搜索、缩放、小地图、保存刷新恢复、1024px 边界和控制台/网络异常。

## 隔离与安全边界

- E2E 只在脚本创建的临时 Chrome profile 中写入 IndexedDB，结束后递归删除该精确目录。
- 只启动脚本记录 PID 的临时 Vite 和 Chrome；不占用、不重启现有 8888 服务。
- `/api/skills/added`、`/api/tasks` 和本机 Runtime 信息在 CDP 层返回只读空数据；不连接真实后端。
- 不调用生成接口、不扣积分、不上传文件、不读取或修改用户账号内画布。

## 风险与后续建议

- 本阶段建立的是核心编辑链路门禁，未覆盖付费生成、真实上传、多人共享和远端同步；这些应在具备专用测试账号与免计费测试渠道后单独验收。
- 画布项目页和 Agent 面板仍是超大组件，后续应按视口、节点操作、生成编排、浮层拆分，但不要在临近上线时与本次验收工程混合提交。
- ZIP 导入导出和大画布性能仍需要独立的容量基准；建议补 100/500/1000 节点场景与内存峰值报告。
