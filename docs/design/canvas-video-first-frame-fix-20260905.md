# 视频悬停播放首帧黑闪修复（2026-09-05）

悬停播放时，封面会持续覆盖尚未出画的播放器，等当前素材的首帧就绪后再揭开。保留已有的 180ms 悬停触发、原声播放、离开暂停、续播和工具栏呈现。修改前基线为 `3a95aa70`；本次代码提交见下方回滚段落。

## 原因与修改

此前节点拿到视频 URL 就把封面替换为播放器，但地址解析完成和 `canplay` 都不等于视频层已经呈现画面，因此播放器的黑色背景会短暂露出。另外，资源加载 hook 在 `eager` 切换时无条件清空同源 URL，会在重复悬停时额外卸载、重建播放器。

- 封面保持同一个 DOM 实例，以不拦截鼠标的覆盖层呈现；等待期间播放器正常加载和绘制。首帧就绪后隐藏覆盖层，离开后重新显示封面。
- 优先使用原生 `requestVideoFrameCallback`，检查资源源、实际视频实例、尺寸、媒体就绪状态和 `seeking`。先恢复续播位置，再等待对应画面，迟到的旧帧不能揭开新素材封面。
- 没有首帧回调的浏览器，在可用画面条件成立后等待两次动画帧并重新检查；已有呈现帧的暂停播放器使用同一后备路径。源重新加载、组件卸载等情况会取消监听和排队回调。
- 缓存读取或下载状态切换时保留已解析的同源 URL。更换素材时同步隔离旧 URL，异步结果同时校验源身份和请求身份，防止乱序结果覆盖当前资源。

首帧回调的含义参见 [MDN requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)；媒体数据事件参见 [MDN loadeddata](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/loadeddata_event)。
